01 Architecture globale

Cron Vercel
6h30 — Next.js API
→

edifio-playwright-worker
POST /v1/scrape · Bearer secret
→
PLACE / FrancMarchés
Playwright headless
Worker Fly.io
→
Webhook Vercel
/api/scraper/webhook
POST résultats · Bearer même secret
→
Supabase
INSERT tenders

Le worker Fly.io est un serveur Fastify + Playwright Chromium qui :

  • Reçoit un ordre de scraping de Vercel (POST /v1/scrape)
  • Répond immédiatement 202 (non-bloquant pour Vercel)
  • Lance le scraping Playwright en arrière-plan (PLACE ou FrancMarchés)
  • Poste les AOs trouvés vers le webhook Vercel (WEBHOOK_TARGET_URL)
  • Se met en veille automatiquement entre les runs (auto-stop Fly Machines)
Sécurité : Le header Authorization: Bearer <SCRAPER_TRIGGER_SECRET> est la seule protection. Ce secret doit être identique côté Vercel (SCRAPER_TRIGGER_SECRET) et côté Fly.io (fly secrets set). Ne le mets jamais dans le dépôt Git.

02 Prérequis

Outils locaux

# Installer le CLI Fly.io (PowerShell — une seule fois)
iwr https://fly.io/install.ps1 -useb | iex

# Vérifier
fly version
# → fly v0.3.x (expected)

# Se connecter à ton compte Fly.io
fly auth login
# → ouvre le navigateur, confirme le login

Compte Fly.io

  • Compte créé sur fly.io (plan Pay-as-you-go minimum)
  • Moyen de paiement ajouté (la VM shared-cpu-2x 2 GB coûte ~$0.0000128/s quand active)
  • Avec auto-stop et une utilisation quotidienne, le coût réel est ~2–5 €/mois

Docker

Docker Desktop doit être en cours d'exécution sur ta machine lors du premier fly deploy. Fly CLI utilise Docker pour builder l'image localement.

Région : Le worker est configuré en région cdg (Paris CDG). Si cdg est saturé, commenter/décommenter le fallback fra dans infra/playwright/fly.toml.

03 Créer le secret partagé

Le SCRAPER_TRIGGER_SECRET doit être un token aléatoire fort (32+ chars). Génère-le une seule fois, stocke-le dans ton gestionnaire de mots de passe, puis utilise la même valeur sur Fly.io et Vercel. 

# Génère un secret fort (PowerShell)
-join ((1..32) | ForEach-Object { [char](Get-Random -Min 65 -Max 122) })

# OU via Node.js (plus propre)
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
# → ex: a3f8e2c1d9b74a6e... (64 chars hex)
Règle d'or : ce secret ne doit jamais apparaître dans un commit Git, dans un message Slack/Teams, ou dans ce document en clair. Stocke-le dans ton gestionnaire de mots de passe.

04 Premier déploiement Fly.io

Avant de déployer : Docker Desktop doit être démarré.

4.1 — Créer l'app (une seule fois)

# Se positionner dans le dossier du worker
cd C:\Dev\edifio-sourcing\infra\playwright

# Créer l'app Fly.io (nom dans fly.toml = edifio-playwright-worker)
fly apps create edifio-playwright-worker
# → App 'edifio-playwright-worker' created in organization 'personal'
Si tu vois "App already exists", c'est normal — passe directement au 4.2.

4.2 — Poser les secrets (voir §5 pour la liste complète)

# Poser les secrets critiques AVANT le premier deploy
fly secrets set \
  SUPABASE_URL="https://TON_PROJECT_REF.supabase.co" \
  SUPABASE_SERVICE_ROLE_KEY="eyJ..." \
  SCRAPER_TRIGGER_SECRET="ton_secret_genere_etape_3" \
  WEBHOOK_TARGET_URL="https://edifio-sourcing.vercel.app/api/scraper/webhook"
# → Les secrets sont chiffrés et stockés dans Fly.io Vault

4.3 — Premier build et déploiement

# Depuis infra/playwright
fly deploy

# Fly.io va :
#  1. Builder l'image Docker localement (Chromium ~800 MB, ~3-5 min)
#  2. Push l'image vers le registry Fly
#  3. Déployer 1 machine sur la région cdg
#  4. Attendre le health check /healthz

# Résultat attendu :
# --> v1 deployed successfully
# --> Monitoring deployment

4.4 — Vérifier le déploiement

# Statut de l'app
fly status

# Health check direct
fly curl /healthz
# → {"status":"ok","version":"1.0.0","browser":"idle"}

06 Variables Vercel côté Next.js

Sur Vercel → ton projet → Settings → Environment Variables, ajouter :

Variable Valeur Env
SCRAPER_BASE_URL https://edifio-playwright-worker.fly.dev Production + Preview
SCRAPER_TRIGGER_SECRET Le même secret qu'en §3 (identique à Fly.io) Production + Preview
Critique : SCRAPER_TRIGGER_SECRET doit être exactement la même valeur côté Vercel et côté Fly.io. Une différence d'un seul caractère (espace, guillemet) casse l'authentification.

Le code Next.js qui déclenche le scraping lit ces deux variables :

// Dans l'API route /api/scraper/trigger (ou le cron Vercel)
const res = await fetch(`${process.env.SCRAPER_BASE_URL}/v1/scrape`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${process.env.SCRAPER_TRIGGER_SECRET}`,
  },
  body: JSON.stringify({
    platform: 'place',
    profileId: profile.id,
    orgId: ALYOS_ORG_ID,
    webhookUrl: `${siteUrl}/api/scraper/webhook`,
    lastRunAt: lastRunAt.toISOString(),
    profileFilters: { keywords: [...], geoZones: [...] },
    credentials: {
      username: process.env.PLACE_USERNAME,
      password: process.env.PLACE_PASSWORD,
    },
  }),
});

07 Tester le worker

7.1 — Health check

# Via fly curl (pas besoin d'auth sur /healthz)
fly curl /healthz
# → {"status":"ok","version":"1.0.0","browser":"idle"}

# Ou via curl classique
curl https://edifio-playwright-worker.fly.dev/healthz

7.2 — Test d'authentification

# Sans token → doit retourner 401
curl -X POST https://edifio-playwright-worker.fly.dev/v1/scrape \
  -H "Content-Type: application/json" \
  -d '{"platform":"place"}'
# → {"error":"unauthorized"}

# Avec mauvais token → 401
curl -X POST https://edifio-playwright-worker.fly.dev/v1/scrape \
  -H "Authorization: Bearer MAUVAIS_SECRET" \
  -H "Content-Type: application/json" \
  -d '{}'
# → {"error":"unauthorized"}

7.3 — Test complet (dry-run FrancMarchés)

# Remplacer TON_SECRET et TON_WEBHOOK_URL par les vraies valeurs
curl -X POST https://edifio-playwright-worker.fly.dev/v1/scrape \
  -H "Authorization: Bearer TON_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "platform": "francmarches",
    "profileId": "test-profile-id",
    "orgId": "ALYOS_ORG_ID_DEPUIS_DB",
    "webhookUrl": "https://edifio-sourcing.vercel.app/api/scraper/webhook",
    "lastRunAt": "2026-01-01T00:00:00Z"
  }'
# → 202 {"runId":"uuid","estimatedDuration":90}
# Le worker répond immédiatement, le scraping est asynchrone
# Vérifier les logs pour suivre la progression (§11)

08 Comptes scrapers (PLACE + FrancMarchés)

8.1 — PLACE (marches-publics.gouv.fr)

  1. Aller sur https://www.marches-publics.gouv.fr
  2. Créer un compte avec l'email steissier@alyosingenierie.fr (ou un email dédié)
  3. Compléter le profil entreprise AlyoS Ingénierie
  4. Confirmer l'email
  5. Poser les variables sur Fly.io : fly secrets set PLACE_USERNAME="..." PLACE_PASSWORD="..."
Le scraper PLACE (infra/playwright/src/scrapers/place.ts) fait une connexion Playwright sur la plateforme PLACE et scrape les AOs selon les filtres du profil de recherche (mots-clés + zones géographiques).

8.2 — FrancMarchés

FrancMarchés ne nécessite pas de compte pour le scraping public. Le scraper accède directement aux AOs publics filtrés par mots-clés et zones. Pas de credentials à configurer.

Recommandation : Commencer par FrancMarchés (sans compte) pour valider le pipeline end-to-end, puis activer PLACE une fois le compte créé.

09 Auto-stop et mise à l'échelle

Configuration actuelle dans infra/playwright/fly.toml :

[http_service]
  auto_stop_machines  = "stop"   # S'éteint après ~5 min d'inactivité
  auto_start_machines = true    # Redémarre à la première requête (~3s)
  min_machines_running = 0      # 0 = peut s'éteindre complètement

[[vm]]
  size    = "shared-cpu-2x"  # 2 vCPU partagés
  memory  = "2gb"           # 2 GB RAM (Chromium en a besoin)
  cpu_kind = "shared"
  cpus    = 2

Comportement :

  • La machine est stoppée entre les runs → coût minimal
  • Au premier appel POST /v1/scrape, Fly.io redémarre la machine en ~3 secondes
  • Le code gère ce délai : Vercel a un timeout de 60s sur son API route de déclenchement
  • Si deux scraping simultanés : la concurrence soft_limit=20 / hard_limit=50 laisse la place

Estimation de coût mensuel

Scénario Fréquence Durée/run Coût/mois
1 plateforme (FrancMarchés) 1×/jour ~90s ~0.50 €
2 plateformes (PLACE + FrancMarchés) 1×/jour ~3–4 min total ~1–2 €
Plusieurs profils 1×/jour ~10 min total ~3–5 €
Budget Fly.io prévu au Gate 6 : 5–15 €/mois (scenario prod avec plusieurs profils). La configuration auto-stop garantit de rester dans cette enveloppe.

12 Rotation des secrets

En cas de fuite du SCRAPER_TRIGGER_SECRET (ou par rotation préventive) :

  1. Générer un nouveau secret (§3)
  2. Mettre à jour côté Fly.io : fly secrets set SCRAPER_TRIGGER_SECRET="NOUVEAU_SECRET"
  3. Mettre à jour côté Vercel : Settings → Environment Variables → SCRAPER_TRIGGER_SECRET
  4. Redéployer Vercel (ou attendre le prochain redéploiement automatique)
  5. Tester avec la commande §7.2
  6. Tracer dans DECISIONS.md : date, raison, agent
Ordre impératif : Mettre à jour Fly.io avant Vercel. Sinon il y a une fenêtre où Vercel envoie l'ancien secret et le worker refuse les requêtes.

Rotation de SUPABASE_SERVICE_ROLE_KEY

# Sur Fly.io
fly secrets set SUPABASE_SERVICE_ROLE_KEY="NOUVELLE_CLE"

# Vérifier que le health check reste vert
fly curl /healthz
