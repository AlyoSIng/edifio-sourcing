# Note de suivi — ADR-011 couche 3 implémentée

**Date** : 2026-05-15 07:34
**Auteur** : [DEV Alex] (Claude Code, sub-agent dev)
**Branche** : `feat/auth-password-pivot`
**Contexte** : finalisation ADR-011 couche 3. Le flow « mot de passe oublié »
ne passe plus par un lien tokenisé Supabase (consommé par le scanner email
d'entreprise AlyoS) — il regénère un mot de passe provisoire envoyé en clair
via Resend, identique au flow invitation admin.

## 1. Ce qui a changé

### Server Actions
- `forgot-password/actions.ts` : `generateLink({type:"recovery"})` + Resend lien
  → `listUsers + filter` + `admin.updateUserById` (password provisoire +
  metadata `must_change_password=true`, `provisional_password_expires_at` +24h,
  `password_reset_at` ISO maintenant) + `sendWelcomeProvisionalPassword`
  variant `reset`. Anti-énumération conservée (toujours `{status:"sent"}`).
- `reset-password/actions.ts` : suppression flow PKCE (`?code` +
  `exchangeCodeForSession`) et flow recovery implicit. Une seule branche
  first-login : user a une session, update password + reset flags, redirect
  `/sourcing/ao-du-jour`.

### Page + Form reset-password
- `page.tsx` : plus de `?code` ni de cas 3 implicit. Détection session unique.
- `ResetPasswordForm.tsx` : plus de prop `code`/`mode` — toujours en mode
  first-login. UI inchangée hors bandeau.

### Callback handlers
- `ClientCallbackHandler.tsx` : retire la branche `#access_token` /
  `setSession`. Garde uniquement la détection `#error=...` → redirect
  `/auth/error?code=...`.
- `auth/callback/page.tsx` : conservé en route legacy. PKCE résiduel
  (`?code`) accepté pour les helpers E2E qui passent encore par
  `generateLink({type:"magiclink"})` historiquement. Erreur en query →
  `/auth/error`.

### Email pipeline
- `welcome-provisional-password.ts` : ajout d'un champ `variant: "welcome" |
  "reset"`. Sujet et intro adaptés ; le reste du body (table identifiants,
  CTA, TTL 24h) est strictement identique entre les deux variants.
- `send.ts` : ajout `sendWelcomeProvisionalPassword`. `sendWelcomeEmail`
  reste exporté comme alias rétrocompatible (variant `welcome` par défaut)
  pour les routes admin. `sendPasswordResetEmail` retiré.
- `templates/password-reset.ts` SUPPRIMÉ.

### Types
- `UserMetadata` enrichi de `password_reset_at?: string | null` (trace audit
  optionnelle, posée par `requestPasswordResetAction`).

### Copy
- `forgot-password/page.tsx` : « lien pour définir un nouveau mot de passe »
  → « nouveau mot de passe provisoire par email ».
- `ForgotPasswordForm.tsx` : bouton « Recevoir un nouveau mot de passe »,
  message succès aligné.
- `design/copy/templates_brevo_v1.md` D.10 réécrit conformément ADR-011.
- `specs/plan_recette_gate7_v1.md` S0.10 aligné.

### Tests E2E
- `e2e/helpers/auth.ts` : `signInWith` ne passe plus par
  `generateLink({type:"magiclink"})` + fragment → login UI complet via
  `auth.admin.createUser` (durable password connu) + saisie form `/login`.
  L'API publique du helper est inchangée — middleware-domain tests OK.
- `e2e/helpers/password.ts` : `getRecoveryLink` → `regenerateProvisionalPasswordFor`.
  Équivalent fonctionnel à `requestPasswordResetAction` côté admin API.
- `e2e/auth-password.spec.ts` S4 : nouveau scénario aligné ADR-011
  (forgot UI → regen provisoire helper → login provisoire → force-redirect
  /reset-password → définitif → /sourcing/ao-du-jour).

## 3. Décisions ad hoc prises en autonomie

1. **`/auth/callback` conservé en route legacy.** Le brief autorisait à
   supprimer si seul l'invite signup admin l'utilisait — mais en réalité
   les helpers E2E middleware utilisaient encore `generateLink({type:"magiclink"})`
   pour bootstrap une session. J'ai migré les helpers vers un login UI
   password durable (plus rapide à valider que de supprimer + casser les
   middleware-domain tests + tout reboot). La page `/auth/callback` reste
   en place avec une branche PKCE résiduelle pour ne pas exploser si un
   ancien lien arrive. À retirer définitivement une fois le routage Supabase
   Site URL ré-aligné sur `/auth/error` (P2, hors scope de cette session).

2. **`sendWelcomeEmail` conservé en alias rétrocompat.** Plutôt que de
   migrer tous les call sites (route admin invite + regenerate), j'ai
   gardé l'API existante en aliasant `variant: "welcome"`. La nouvelle
   fonction `sendWelcomeProvisionalPassword` accepte explicitement le
   variant. Évite un diff inutile sur les routes admin.

3. **`password_reset_at` ajouté au type `UserMetadata`** (au lieu d'un cast
   `as Record<string, unknown>` opaque). Tracé en clair dans le shape pour
   préparer l'audit log post-ORM. Optionnel donc rétrocompatible.

4. **Plan recette S0.10 réécrit dans la foulée.** Le brief mentionnait
   `specs/plan_recette_gate7_v1.md` sans pointer S0.10 explicitement, mais
   c'est la ligne qui décrit le flow forgot-password. À valider Board si
   formulation OK.
