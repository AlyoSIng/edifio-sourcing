## 5 sous-étapes accomplies

1. **Tooling tests** : install `@supabase/ssr 0.10.3` + `@supabase/supabase-js 2.105.4` (deps), `vitest 4.1.5` + `@vitest/coverage-v8 4.1.5` + `@playwright/test 1.59.1` + `@next/env 16.2.6` (devDeps). Configs `vitest.config.ts` (env node, coverage scopée `src/lib/auth/**` au seuil 90 %) + `playwright.config.ts` (chromium, webServer auto `pnpm dev`, env via `loadEnvConfig`). Chromium installé via `pnpm exec playwright install chromium`.

2. **Helpers Supabase SSR** (`src/lib/supabase/`) :
   - `server.ts` : `createSupabaseServerClient` (cookies via `next/headers` + try/catch pour Server Components) + `createSupabaseAdminClient` (service_role, no-op cookies).
   - `browser.ts` : `createSupabaseBrowserClient` pour les Client Components.
   - **Pattern `getAll`/`setAll`** (@supabase/ssr 0.6+) au lieu de l'ancien `get`/`set`/`remove` deprecated — critique pour la propagation des cookies entre callback et middleware.

3. **Server Action** `src/app/login/actions.ts` :
   - `signInWithOtpAction(prevState, formData)` validée Conventional Commits.
   - Validation côté serveur AVANT envoi : regex email + `isAuthorizedEmail()` (lib auth étape 2). Refus pré-envoi si domaine non Alyos.
   - Type `LoginState = { idle | error | sent }` exposé pour `useFormState`.

4. **Callback `/auth/callback` — dual-flow** :
   - `page.tsx` (Server Component) : gère le **PKCE flow** (`?code=` → `exchangeCodeForSession` → redirect), `redirect` côté `next/navigation`. Garde anti-open-redirect `sanitizeNext` (rejette `//`, `\`, schémas absolus).
   - `ClientCallbackHandler.tsx` (Client Component) : gère l'**implicit flow** (`#access_token=...` côté navigateur uniquement) — lit le fragment, appelle `supabase.auth.setSession()`, puis `router.replace(next)`. Permet aux tests E2E avec `auth.admin.generateLink` de fonctionner (admin ne supporte pas PKCE).

5. **`/login` wire-up** :
   - `LoginForm.tsx` Client Component : `useFormState` + `useFormStatus`, 3 états (idle/error/sent), état `sent` conforme M7 (check + message).
   - `page.tsx` Server Component : lit `?error=magic_link_invalid`, affiche bandeau d'erreur si présent, délègue le form au CC.

## Incidents fixés en cours de route

1. **Middleware au mauvais endroit** : `middleware.ts` à la racine n'était PAS détecté par Next.js (mode `src-dir` → cherche dans `src/`). Déplacé en `src/middleware.ts`. **Bloquant Gate 6 latent** — si non détecté à l'étape 3, le middleware n'aurait jamais protégé `/sourcing/*` en prod.
2. **Matcher trop complexe** : pattern proposé en spec §3.1 avec `.*\.(?:svg|png|...)$` non supporté par path-to-regexp. Remplacé par le pattern canonique Next.js.
3. **Service_role key longueur 46** (au lieu de ~200) : mauvaise clé copiée initialement. Marc a re-copié la vraie `service_role` JWT.
4. **API cookies deprecated** : `get`/`set`/`remove` ne propage plus correctement les sessions en @supabase/ssr 0.6+. Migré vers `getAll`/`setAll`.
5. **Implicit flow via admin** : `auth.admin.generateLink({type:"magiclink"})` ne produit pas de PKCE link → fragment au lieu de `?code=`. Callback étendu pour gérer les deux flows.
6. **signOut trop précoce** dans le test C4 : signInWith landait sur `/sourcing/ao-du-jour` (route protégée), middleware déclenchait `signOut` immédiat avant que le test puisse vérifier `/forbidden`. Fix : `redirectTo=/auth/callback?next=/` pour landrer sur la route publique avant les checks du test.
