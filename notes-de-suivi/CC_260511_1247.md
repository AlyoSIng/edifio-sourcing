## Ce qui se passe au push

1. GitHub Actions exécute les 6 jobs en parallèle (~3-5 min cumulé).
2. Vercel détecte le push, build et déploie un preview à l'URL
   `https://edifio-sourcing-git-feat-ci-vercel-*.vercel.app`.
3. Le bot Vercel commente la PR avec le lien preview.
4. Les checks « ci-* » apparaissent sur la PR. Merge bloqué tant qu'un
   check est rouge ou pending.

## Test manuel post-merge

- Ouvrir l'URL preview Vercel
- `/` : home publique, lien « Accéder à edifio Sourcing »
- `/sourcing/ao-du-jour` (lien) → redirect vers `/login?next=/sourcing/ao-du-jour`
- `/login` : formulaire actif, saisir un email AlyoS → bouton « Recevoir mon lien »
- Vérifier que le magic-link arrive dans la boîte mail
- Cliquer le lien → callback (`/auth/callback?code=...` ou `#access_token=...`)
  → exchange/setSession → redirect `/sourcing/ao-du-jour` (404 page mais URL OK)
- Tester avec un email non AlyoS (ex. perso) : refus pré-envoi côté form
  (validation domaine côté Server Action AVANT envoi du magic-link)
